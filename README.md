# physics-arcade

**Can AI models predict what happens next in simple physics games?**
**[Leaderboard, failure gallery and a human challenge →](https://terrybtf.github.io/physics-arcade/)**

physics-arcade is a benchmark of small 2D physics games. A model watches the first
0.4 s of a shot, before anything collides, and has to predict the outcome. Every
episode is generated by a physics simulator, so there are unlimited levels, exact
ground truth, and controllable difficulty.

† Read exact launch and position numbers instead of images; the game-specific rule
ignores most of the physics (collapses, cushion bounces and combinations, mass and
steps). Pool's simulator row shows how unforgiving pool is: a 0.5° aim error already
changes many outcomes.

What stands out:

- **Dominoes defeats both models.** Qwen3-VL-4B answers "every domino falls" in 294 of
  300 episodes and lands exactly at chance. Qwen3-VL-8B does worse than chance on the flat
  style: it predicts that short, evenly spaced chains stop after the first domino (85 % of
  those dominoes actually fall) and that long chains with gaps, heavy dominoes and steps
  fall completely (only 30 % do). Its guesses track chain length, not gaps or mass.
- **Pool is where vision models do best**, and on hard tables 4B beats the straight-line
  rule (0.76 vs 0.69), which fails on bank and combination shots.
- **Bigger is not better here:** 8B is no better than 4B on Catapult or Pool.
- **Prompt wording matters.** Clarifying the answer format (no change to the task) moved
  4B on Catapult from 0.55 to 0.63. All numbers above use the same prompt
  (`physics_arcade.vlm`).

Per-difficulty numbers: `physics-arcade leaderboard`. Raw model answers, including the
reasoning text, are in [`results/v1/`](results/v1/).

## How it works

**Outcome track (main).** For each labeled target (robot, ball, domino), predict whether
the event happens (survives, potted, falls). Models get the first frame with target ids
and 4 frames of the shot (images only).

**Collisions are chaotic.** Replaying an episode with a launch that differs by 0.25 % in
speed or 0.1° in angle can change the result, so a single simulation is not a fair
answer key. Each episode is replayed 50 times under such tiny perturbations; a target's
label is the fraction of replays in which the event happens. Scoring:

- **Stable balanced accuracy (headline):** on targets whose fate agrees in ≥ 90 % of
  replays, against the majority fate. Chance is 0.50.
- **Brier score:** on all targets; rewards calibrated probabilities. Models may answer
  with a probability per target.

**Difficulty tiers.** Every game has easy / medium / hard levels (100 episodes each), and
results are broken down by tier.

| Game | easy | medium | hard |
|---|---|---|---|
| Catapult | one structure | two structures | full field, tall towers |
| Pool | 1–2 balls, direct shots | 3–5 balls, bank shots | 6–9 balls, clusters, combination shots |
| Dominoes | 4–6 equal dominoes | 6–8, mixed heights, heavy dominoes | 8–11, plus raised steps |

**Two render styles** with identical physics: `flat` (one solid color per object class)
and `cartoon` (textured, game-like). The style gap shows how much of a model's error is
about seeing the scene rather than about physics. All artwork is original and procedural.

**Rollout track (video world models).** Generate the remaining 5.6 s as video. Predicted
frames are segmented back into object classes (by color, or with a color table fitted
on cartoon frames) and compared with the simulator's masks (mean IoU).

## Quick start

```bash
uv sync
D=data/catapult_v1
uv run physics-arcade generate --game catapult --out $D --n 100            # add --style cartoon
uv run physics-arcade baseline --data $D --name ballistic --out preds/ballistic.jsonl
uv run physics-arcade eval-outcome --data $D --pred preds/ballistic.jsonl
uv run physics-arcade leaderboard --data $D "Ballistic=preds/ballistic.jsonl"
uv run physics-arcade predictability --data $D --out analysis/catapult.jsonl   # how chaotic is each episode?
uv run physics-arcade baseline --data $D --name oracle --out preds/oracle  # rollout track sanity check
uv run physics-arcade eval-rollout --data $D --pred preds/oracle
uv run physics-arcade visualize --data $D --pred preds/oracle --ep hard_0003 --out viz/hard_0003.mp4
```

Dataset layout: `tasks.jsonl` and `inputs/<id>/` (context frames, context video, first
frame with target ids) are what a model may see; `answers/` holds the hidden labels and
masks. Outcome predictions are JSON lines `{"id": ..., "ids": [targets for which the
event happens], "p": {"<id>": probability}}` (`p` optional).

## Evaluating a model

`physics_arcade.vlm` holds the shared prompt, answer parsing and a resumable loop; a
backend only maps a list of image/text parts to a reply, so adding an API model is a few
lines. `models/qwen_vl/` runs Qwen3-VL locally (4B in bf16 or 8B in FP8 fit in 16 GB):

```bash
cd models/qwen_vl && ./setup.sh
.venv/bin/python run_qwen_vl.py --model Qwen/Qwen3-VL-8B-Instruct-FP8 \
    --data ../../data/catapult_v1 --out ../../preds/qwen3vl_8b_catapult.jsonl
```

`models/cosmos/` runs NVIDIA Cosmos-Predict2-2B-Video2World for the rollout track
(Catapult prompts; needs Hugging Face access to the gated Cosmos and guardrail repos).
`models/cosmos/dry_run.py` pushes ground truth through the same 16 fps resampling path to
measure its ceiling.

## Website

The site in `docs/` (GitHub Pages) is static. `uv run python scripts/build_site.py`
rebuilds its data and media from the cartoon datasets and `results/v1/`; preview it with
`python3 -m http.server --directory docs`.

## Adding a game

A game is a `physics_arcade.core.game.Game`: physics, a flat and a cartoon renderer, a
level generator per difficulty, a deterministic `replay` that accepts perturbations, and
the question text. Dataset writing, labels, scoring, segmentation, visualization and the
VLM harness are shared. See `src/physics_arcade/games/` for the three existing games.
